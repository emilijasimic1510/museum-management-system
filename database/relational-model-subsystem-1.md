# Relational model — subsystem 1

Sources: the approved specification (sections 7–10 and 12), the EER diagrams, and the confirmed exhibition–participation relationship. The original source documents remain unchanged.

## Mapping

Standalone IDs use `bigint generated by default as identity`; composite keys retain their constituent IDs. Text uses `text`, years `integer`, area/price `numeric(19,2)`, flags `boolean`, and business timestamps `timestamp with time zone` (Java `Instant`). The exhibit creation period is text because approximate periods are permitted.

SQL identifiers retain the domain terminology used by the implementation.

All foreign keys use `ON DELETE RESTRICT ON UPDATE RESTRICT`. Primary and unique keys receive indexes automatically. Additional indexes cover foreign keys that are not the leading part of a composite key, major resource names, and admission start times.

## Design decisions

- Authorship is an M:N relationship with attributes, mapped through a join table and JPA `@EmbeddedId`, without an artificial ID.
- An exhibition price is identification-dependent: `@EmbeddedId` contains all three key parts and `@MapsId` associates the exhibition.
- Participation retains its own `id_ucesca`; there is no additional exhibition join table. The exhibition/exhibit pair is not unique, so repeated placements are possible.
- QR data and digital content belong to participation, not directly to an exhibit. QR rendering, TTS, and graph recommendations were added outside the initial schema phase.
- Every exhibition requires at least one admission time at creation. POST includes a nonempty `terms` list, saved atomically. A deferred PostgreSQL constraint trigger checks the minimum at transaction end; services prevent removing or moving the last admission time.
- The specification does not define nullability for every descriptive attribute. Optional descriptive fields remain optional; required names, addresses, and operational fields are validated at the API boundary.
- CHECK constraints enforce exhibition end after start, allowed exhibition/admission statuses, nonnegative admission capacity, and content types `SLIKA`/`TEKST`/`AUDIO`. The initial model does not invent additional positivity checks for price, area, or years.
- Admission times must end after they start and fit within their exhibition. Services and database triggers validate this when either interval changes.
- Overlapping exhibitions in a hall are prevented by service checks and a PostgreSQL exclusion constraint using `btree_gist`. Intervals are half-open `[start,end)`; cancelled exhibitions do not occupy the hall.
- Deleting a parent with dependent records returns 409 rather than cascading. Museums have the existing `aktivan` flag; halls have no additional deactivation field. Sales/visit history is protected by the later subsystem.

## REST contract

Resource routes are `/api/museums`, `/api/halls`, `/api/exhibitions`, and `/api/exhibition-terms`. They support collection GET/POST and item GET/PUT/DELETE. Responses use 200/201/204; invalid input returns 400, missing resources or parents 404, and business/database conflicts 409. DTO fields are English; SQL names retain the implemented domain identifiers. Entities are not serialized directly.

Public catalog reads and protected management writes follow the current [catalog API rules](../backend/CATALOG_API.md). The local profile does not bypass write authorization. The original subsystem-only implementation preceded JWT integration; its historical anonymous local CRUD behavior no longer describes the current application.
